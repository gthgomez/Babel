# Local run review

Inventory existing evidence, then review the last 24 hours:

```sh
babel runs inventory --source ./runs --catalog ./local-catalog.sqlite
babel runs review --catalog ./local-catalog.sqlite
babel runs review --catalog ./local-catalog.sqlite --last-hours 24 --until 2026-10-27T16:00:00Z --json
```

`review` opens an **existing, checkpointed** derived catalog with SQLite immutable read-only access, without migrations or sidecar creation. File/parent symlinks are canonicalized before inspecting sidecars; hardlinked database files are refused because their WAL owner is ambiguous. A nonempty WAL is rejected: close inventory/other writers before review. A catalog/WAL change during review fails rather than silently ignoring live evidence. `--until` rejects explicitly empty values and impossible calendar dates instead of rolling them into another month. It does not ingest, replay commands, regrade evidence, run models, activate telemetry, schedule anything, upload data, or modify canonical evidence. `inventory` remains the separate explicit ingestion operation. A scheduler may opt in to calling this command; none is installed or enabled.

The window uses run manifest `created_at` normalized by SQLite date parsing: inclusive start, exclusive end. Undated/invalid-date runs are excluded and counted. Runs are selected by capture time, not each incident's timestamp; events outside the window inside a selected run remain included. At most 1,000 runs are reported (each with at most 20 observation references, 50 corrections and 20 cluster lineage links; per-record truncation flags expose omitted references); a truncation warning requires a narrower window. Local catalogs can be stale: inventory separately to refresh them. No source is silently re-read by review.

Frequency uses distinct hashed task IDs from `user_submitted` events only when one complete run has a single task ID and no unattributed task submission. Multiple-task, malformed, truncated, missing-ID and older extracted runs remain unattributed. A session, retry, run or case is not an independent task. Task IDs must come from their producer; the report cannot independently establish their correctness. Task frequency is a lower bound when unattributed runs exist. Per-cluster task counts overlap and must not be summed. Ranking is deterministic: failed distinct tasks, affected distinct tasks, then cluster ID. Evaluator-correction assertions across the full annotation history are excluded from failed-product-task priority pending review, even when displayed history is truncated; their original FAIL remains visible. Occurrence counts remain separate.

Run entries expose original task assessment, confidence, opaque observation/run/extraction receipt references, observed provider retry schedules (not inferred executed retries) and denied completion decisions. A denied completion is labelled a completion block, not generalized into user blocking. Clarification and wider friction coverage remain unknown. Missing cost remains unknown; available ledger entries are identified without summing potentially overlapping estimates. Execution exit codes, agent claims, terminal status and passing tests alone cannot establish user task success. Current historical adapters lack a task-correctness contract, so ordinary historical records usually remain UNKNOWN. Controlled tests use an independent artifact evaluator through the existing typed catalog ingestion boundary; this does not extend historical normalization.

The existing cluster `suspected_cause`, `candidate_fix`, `validated_fix` fields drive review status. Their content stays withheld: the report gives presence/status and a resolvable cluster owner reference. Use `babel runs show <clusterId> --catalog <path>` to inspect signature, supporting run, trial, observation, receipt, correction and lineage references through the same immutable reader. A fix owner is the existing cluster record, not a fabricated fix entity. External lineage targets explicitly have no catalog lookup when their entityRef is null; their raw content stays withheld. Receipt lookup exposes the locator digest, not the original path; source investigation still requires the original inventory root. Existing lineage assertions appear as typed references. Even `validated_fix` means **recorded, independently unverified by this command**. Resolution and before/after qualification remain NOT_ESTABLISHED; a recorded link or historical playback cannot certify a current fix or absence of recurrence. Inspect linked records and obtain fresh task-specific validation separately. No heuristic diagnoses root cause.

`RunIntelligenceCatalog.recordAssessmentCorrection()` appends a versioned, review-only annotation for an existing trial. Its evaluation version cannot be overwritten with a different result. The original observations and derived grade remain intact, and every correction version remains visible. An evaluator bug is distinguished from an evidence update. A corrected CSV evaluation for a Unicode subdirectory must retain v1 FAIL and v2 PASS; it does not imply a product repair. Corrections are explicit trusted local review inputs, never inferred from prose or applied automatically. New independent evidence must pass its own authority/admission requirements before any certification claim.

Privacy defaults are metadata-only. No prompts, file contents, command/error bodies, paths, evaluator text or suspected-cause/fix prose appear in the report. Source references are local opaque catalog IDs, usable with `runs show`. Task/version/external-evidence tokens identify minimized metadata rather than lookup entities; report output is not an export of source material. Unkeyed hashes are not confidentiality protection for guessable identifiers. Treat catalogs and reports as local evidence with ordinary access controls. No new event store, service, dashboard, model or automatic repair loop is introduced.
