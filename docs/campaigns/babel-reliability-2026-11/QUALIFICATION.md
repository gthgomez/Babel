# Release qualification contract — independent and artifact-bound

The core question is whether a person can install Babel, choose an authorized provider and execution profile, state a normal coding task, get a correct final tree, and understand exactly which requirements were proven. **Scripted transport verifies harness decisions; real model competence requires a separate authorized live trial.**

## Evidence cell

Every trial records source commit, **artifact digest** (npm/source-packed/Windows Setup/portable/AppImage distinct), OS/Node/Electron, clean isolated home and project, effective execution profile, entrypoint/mode, provider/observed model, frozen user task+required preservation clauses, pre/post tree hashes, actual tool effects, physical provider attempts, verifier receipt scope/currentness, independent grader verdict, terminal status, exit, JSON, UI, durable event, cost known/unknown and unsettled descendants.

Keep grader and hidden checks outside the candidate worktree. Isolate ambient keys, networks and previous run directories before inference imports. Never allow the candidate to overwrite the oracle. No paid calls in this no-key lane.

Run controls in deterministic isolation and record skipped/unavailable cells explicitly. A green test that does not exercise the requested semantics is insufficient. Never silently relabel untested cells as verified.

## Delivery bar

- **No false successes** or stale-proof regressions in deterministic mandatory negatives.
- Expected true positives certify only when obligation, evidence/currentness, effects and authority genuinely align.
- All entrypoints and platform/mode claims require **exact installed artifact** journeys; no source-build or HTML simulation substitutes for native Windows qualification.
- Required GitHub protection/CI, independent PR review and release signing/provenance decisions follow public `AGENTS.md`.
- Do **not** claim a statistical 0% failure rate from zero observed failures: report numerator/denominator and uncertainty.
- Only a later explicitly authorized, capped matched-model test may claim live coding reliability. Use hidden task graders and a minimal baseline; record false success, false block, requirement coverage, interventions, time to useful action and cost per externally solved task.
